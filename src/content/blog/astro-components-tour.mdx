`@prosefly/astro-components` is the shared MDX layer used by Lotus and Dahlia. It exists because
technical articles regularly need more structure than Markdown provides, but that structure should
not tie the writing to one documentation theme.

This page renders every public component from version 0.7.1 inside Aster. It is both a tour and a
portability test: Aster supplies its own layouts, typography, colors, and spacing while the package
supplies content structure and focused interactions.

<Callout type="note" title="One integration">
  Aster registers `proseflyComponents()` once. The integration supplies shared
  Markdown transforms, gallery assets, and Iconify preloading.
</Callout>

The examples stay inside one article on purpose. A component can look convincing in an isolated
catalog and still feel too heavy when surrounded by real headings, paragraphs, and code. Seeing the
whole set in sequence makes the intended hierarchy clearer.

## Badges, icons, and callouts

Badges carry short metadata without interrupting a paragraph:

<Badge>Astro 7</Badge> <Badge color="accent">MDX</Badge>
<Badge color="success">Stable</Badge> <Badge color="warning">Private</Badge>

Icons can be decorative or carry an accessible title. <Icon name="lucide:sparkles" /> This icon is
decorative; <Icon name="lucide:triangle-alert" title="Warning" /> this one announces its meaning.

<Callout type="tip" title="Use the lightest component that explains the idea">
  A badge labels, an icon cues, and a callout interrupts. Choosing between them
  is part of writing the page.
</Callout>

   ```sh
   pnpm add @prosefly/astro-components
   ```

3. **Import components in MDX.**

   Keep ordinary prose in Markdown and reach for components only when structure helps.

## Choosing the smallest useful component

The package is not meant to replace ordinary Markdown. Most sentences, lists, links, images, and
code blocks should remain native content. A component earns its place when it adds a relationship or
behavior that Markdown cannot express clearly.

<CardGrid>
  <Card title="Label">
    Use a badge for compact status or category metadata that belongs beside the
    prose.
  </Card>
  <Card title="Interrupt">
    Use a callout when a note, warning, or recommendation should change how the
    reader interprets the surrounding section.
  </Card>
  <Card title="Organize">
    Use cards, steps, tabs, accordions, or a file tree when the relationship
    between several pieces is the point.
  </Card>
  <Card title="Enhance media">
    Use a gallery, embed, or audio player when native media needs grouping,
    metadata, or focused controls.
  </Card>
</CardGrid>

That restraint keeps an MDX page readable in source form and makes the component API easier to
maintain. The important boundary is unchanged across every example: components supply structure and
behavior, while the host site supplies the visual system.
